# 3.3 Technical Scope

Two parts, in this order.

## Part 1: technical scope (within the section's word budget)
Ground everything in the ledger: `non_catalogue`, `integrations`, `tech_dev` and `workstreams`.
- Non-catalogue SAP tools and modules in scope: name them.
- Custom development: the RICEFW/WRICEF objects and Fiori apps. You may give counts that the
  `tech_dev` view states, as bare numbers.
- The technical workstreams the ledger carries: Basis environments, security and authorisations,
  analytics, and data migration at scope level only. The method of data migration belongs to the
  Data Migration Approach section.
- An item whose status is Out of Scope is not described here; it belongs to Scope Exclusions.
- No effort, cost or rates (see the proposal-writing figure rules).

## Part 2: integrations sub-section (outside the word ceiling)
Write this only when `non_catalogue` or `integrations` has at least one item.
1. Add the sub-heading `### Third-Party Integrations - Solution Approach`.
2. Write the solution approach for each item, following the proposal-writing skill's
   `reference/integrations.md`.
3. If `integrations` has at least one third-party system **and** `effort_detail` is not withheld,
   put `{{table:integration_effort}}` on its own line right after the sub-section. That is the
   indicative effort per integration, rendered from the ledger. Never type the efforts yourself.
