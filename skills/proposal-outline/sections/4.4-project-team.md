# 4.4 Project Team (intro before `{{table:resource_plan}}`)

Briefly introduce the proposed delivery team structure and staffing model in 3-4 sentences before
the resource plan tables that follow. Cover the onsite/offshore mix and the fact that every module
has a named lead. Do not state FTE numbers or man-months yourself; the tables do that.

Disclosure conditions:
- Say "every module has a named lead" only when the `team` view shows a lead role for each module
  in scope.
- Describe the onsite/offshore mix only when `resource_location` is not withheld.
- When `resource_allocation` is withheld, the renderer shows a Phase | Skill table only, with no
  month columns, man-months or locations. Describe which roles engage in which phases, and nothing
  about allocation.

The renderer appends, when allocation is disclosed:
1. a Delivery Waves overview, only for more than one wave;
2. one FTE-by-month grid per wave (Skill | Location | M1..Mn | Total Man-months, with phase-band,
   onsite, offshore and grand-total rows);
3. a combined programme staffing table when there are several waves;
4. a closing note. With `combine_resource_effort: true` (the default here), resource effort is
   presented together with module effort as one view: the lead and programme-management effort
   is additional to the module effort. With `false`, man-months appear here and person-day effort
   separately in the effort section.

If the client asked for named roles, a team-structure narrative or key-personnel profiles
(`excerpts:4.4` or a mapped requirement), answer it with roles from `team`. Never invent named
individuals or CVs.
