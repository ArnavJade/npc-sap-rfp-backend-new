# Supporting visuals and the RACI convention

## One optional supporting visual per section
A section may carry ONE qualitative visual of your own when it makes the content easier to scan:
- a pipe table (at most 6 columns x 12 rows): deliverables by phase, risks and mitigations,
  roles and responsibilities, governance forums and cadence, test cycles and entry/exit criteria;
- or a numbered step list for a sequence (cutover steps, migration cycle, escalation path).
Rules: no figures in it (no effort, cost, FTE, durations beyond stated ledger facts); never a copy
of a table or diagram another section owns (see placeholders.md); one header row; short cells.
Skip the visual when the section is short or has no client-specific material.

## RACI convention (4.6 and any client-required responsibility matrix)
The renderer appends the standard RACI matrix in 4.6 - write only its 2-3 sentence introduction.
- Columns: Client Sponsor, Client SME / Core Team, YASH Project Manager, YASH Solution Architect,
  YASH Consultants.
- Rows: the cross-cutting SAP Activate delivery activities (planning and governance through
  hypercare). Modules are not rows.
- Exactly ONE Accountable (A) per activity; R = Responsible, C = Consulted, I = Informed.
- If the RFP prescribes its own roles or responsibility model, echo it in the introduction. A
  client-required section that asks for a different matrix may include its own pipe table with the
  same conventions (one A per row, the client's role names).
